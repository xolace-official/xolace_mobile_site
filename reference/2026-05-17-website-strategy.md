### 4.6 PostHog Analytics — Install + Full Event List

**PostHog is not yet in package.json.** Install first:
```bash
bun add posthog-js
```

**New environment variable needed (add to `.env` and Vercel):**
```
NEXT_PUBLIC_POSTHOG_KEY=phc_XXXX      # get from PostHog dashboard
NEXT_PUBLIC_POSTHOG_HOST=https://app.posthog.com
```

**Create `providers/posthog-provider.tsx`:**
```tsx
"use client"
import posthog from "posthog-js"
import { PostHogProvider as PHProvider } from "posthog-js/react"
import { useEffect } from "react"

export function PostHogProvider({ children }: { children: React.ReactNode }) {
  useEffect(() => {
    posthog.init(process.env.NEXT_PUBLIC_POSTHOG_KEY!, {
      api_host: process.env.NEXT_PUBLIC_POSTHOG_HOST,
      capture_pageview: true,
      capture_pageleave: true,  // enables scroll depth tracking
    })
  }, [])
  return <PHProvider client={posthog}>{children}</PHProvider>
}
```

**Wire into `app/layout.tsx`:** wrap `{children}` with `<PostHogProvider>`.

**Custom events to instrument (beyond automatic pageview):**

| Event name | Where to fire | What it tells us |
|------------|---------------|-----------------|
| `cta_click_hero_download` | Hero "Download free ↓" link | Did hero copy convert? |
| `cta_click_app_store` | Any App Store badge click | iOS vs Android split |
| `cta_click_play_store` | Any Play Store badge click | iOS vs Android split |
| `cta_click_support_xolace` | Support Xolace form submit | Community interest signal |
| `cta_click_sticky_bar_app_store` | Sticky bar App Store | Mobile conversion rate |
| `cta_click_sticky_bar_play_store` | Sticky bar Play Store | Mobile conversion rate |
| `section_view_[name]` | Each landing section entering viewport | Drop-off funnel |

**Scroll depth:** enabled automatically when `capture_pageleave: true` is set in `posthog.init`. PostHog records `$scroll_depth` as a property on the pageleave event. No custom hook needed.

**Corrected time estimate:** 2-3 hours total (install + provider + 7 custom events + testing).

### 4.7 Sticky Mobile Download Bar

**Confirmed:** `id="download"` already exists on `<section>` in `components/landing/launch-section.tsx:3`. The sticky bar hides when this section enters the viewport.

**Create `components/shared/mobile-download-bar.tsx`:**
```tsx
"use client"
import { useEffect, useRef, useState } from "react"
import Image from "next/image"
import posthog from "posthog-js"

export function MobileDownloadBar() {
  const [visible, setVisible] = useState(false)
  const [atDownload, setAtDownload] = useState(false)

  useEffect(() => {
    // Show bar after user scrolls past hero (~100px)
    const onScroll = () => setVisible(window.scrollY > 100)
    window.addEventListener("scroll", onScroll, { passive: true })

    // Hide when LaunchSection is in view
    const target = document.getElementById("download")
    if (!target) return
    const observer = new IntersectionObserver(
      ([entry]) => setAtDownload(entry.isIntersecting),
      { threshold: 0.1 }
    )
    observer.observe(target)

    return () => {
      window.removeEventListener("scroll", onScroll)
      observer.disconnect()
    }
  }, [])

  if (!visible || atDownload) return null

  return (
    <div className="fixed bottom-0 left-0 right-0 z-50 md:hidden
                    bg-background/80 backdrop-blur-xl border-t border-border/40
                    px-6 py-3 flex items-center justify-center gap-4">
      <a href="https://apps.apple.com/gh/app/xolace/id6761601429"
         target="_blank" rel="noopener noreferrer"
         onClick={() => posthog.capture("cta_click_sticky_bar_app_store")}>
        <Image src="/images/app-store-mobile.png" alt="App Store"
               width={120} height={40} className="h-10 w-auto dark:hidden" />
        <Image src="/images/app-store-mobile-dark.png" alt="App Store"
               width={120} height={40} className="h-10 w-auto hidden dark:block" />
      </a>
      <a href="https://play.google.com/store/apps/details?id=com.xolaceincorg.xolace"
         target="_blank" rel="noopener noreferrer"
         onClick={() => posthog.capture("cta_click_sticky_bar_play_store")}>
        <Image src="/images/play-store-light.png" alt="Google Play"
               width={120} height={40} className="h-10 w-auto dark:hidden" />
        <Image src="/images/play-store-dark.png" alt="Google Play"
               width={120} height={40} className="h-10 w-auto hidden dark:block" />
      </a>
    </div>
  )
}
```

**Add to `components/landing/page/HomePage.tsx`** alongside `<SmoothScroll>`.

**Badge images confirmed in `/public/images/`:** `app-store-mobile.png`, `app-store-mobile-dark.png`, `play-store-light.png`, `play-store-dark.png`.

## 5. Flux Mascot — Integration Spec

**Name:** Flux
**Shape:** Flame/teardrop with rainbow gradient (orange/yellow → pink → purple → blue)
**Signature prop:** Glowing geometric crystal/gem (represents emotional clarity)
**Pose system:** Generated per use case — any pose needed, not limited to a fixed set
**Animation format:** MP4 currently. Lottie to be explored (better for web).

### Asset naming convention

Store all Flux assets in `/public/flux/`:
```
/public/flux/
  hero-idle.mp4          — looping idle for hero section
  launch-celebrate.mp4   — one-shot for LaunchSection
  404-lost.mp4           — looping for 404 page
  about-warm.png         — still image for /about page
  press-confident.png    — still image for /press page
  trust-protective.png   — still image for TrustSection
  how-it-works-1.png     — listening pose (step 1)
  how-it-works-2.png     — gem brightening pose (step 2)
  how-it-works-3.png     — open/released pose (step 3)
```

### Placement rules

| Location | Pose | Animation | Gem state | Notes |
|----------|------|-----------|-----------|-------|
| Hero | Quiet, inward | Yes — looping idle (slow breathing, gem pulse) | Dimly glowing | MP4 with matching solid background OR `.webm` for transparency |
| ProblemSection | **None** | **No** | — | Heavy vignettes breathe alone — no Flux here |
| HowItWorks step 1 | Listening/receiving | No — still image | Dim | |
| HowItWorks step 2 | Alert, focused | No — still image | Brightening | |
| HowItWorks step 3 | Open, released | No — still image | Fully glowing | |
| TrustSection | Protective/cradling | No — still image | Steady glow | |
| LaunchSection | Most open/joyful | Yes — one-shot on scroll-into-view | Brilliant | Plays once, does not loop |
| `/about` | Warm, grounded | No — still image | Gentle glow | Next to team section header |
| `/press` | Confident, upright | No — still image | Steady | Top-right of page |
| `404` | Lost but curious | Yes — short loop | Flickering slightly | Turns error into brand moment |
| Phase 2: mini-Mirror | Listens → reacts | Yes — reacts to typing | Dim → bright | Highest-impact use |
| Blog post headers | Matched to article emotion | No — still image | Context-dependent | One image per article |

### Gem brightness rule
Flux's gem tracks the emotional arc of the page. Dim at the heavy problem sections. Glowing at clarity, download, and celebration moments. This makes Flux a narrative device with a consistent internal logic — not just decoration.

### MP4 implementation pattern
```tsx
// Looping (hero idle, 404):
<video autoPlay loop muted playsInline src="/flux/hero-idle.mp4"
       className="w-48 h-48 object-contain" />

// One-shot (LaunchSection):
<video autoPlay muted playsInline src="/flux/launch-celebrate.mp4"
       className="w-48 h-48 object-contain" />
```

### Transparent background options
- Best: export as `.webm` with alpha channel
- Acceptable: match the MP4 background color to the section background exactly
- Fallback: CSS `mix-blend-mode: multiply` or `screen` (works for simple cases, test against both light and dark mode)
